# Reproduction guide

## Levels

| Level | What is reproduced | Needs | Hardware |
|---|---|---|---|
| 1 | Every figure from its source data, with the statistics stored next to it | this repository | CPU |
| 2 | Accuracies, retention and source-side measures recomputed from trained networks | + P1, P2, P3 | GPU recommended |
| 3 | Networks retrained from code, configurations and seeds | + P1 (or retrain P1 too) | GPU |

Coverage of Level 2: pretrained cores (Figs. 2, 7d, S1, S2, S11), Phase-F scalar-gain models (Figs. 6, S5, S8, 7a), E0.9a (S7), E6 and rescaling models (Figs. 7b–e, S12). The 4 × 4 experiments (Figs. 3–5, S4), the factorial path-invariance models (S2), the navigation-interface refits (S9) and the full-finetune conditions are reproduced at Levels 1 and 3.

## Seeds and data generation

- Navigation sources 6101–6110 and paired delayed-reconstruction sources 7101–7110 (`plan.json → source_pairs`, `configs/frozen_plan/config_frozen.yaml`).
- 4 × 4 tasks: three target-training repeats per source block with the seeds listed in `plan.json` (`main_target_seeds`, `factorial_target_seeds`); trials are random walks generated by `code/gpm_cmap/data/graph_tasks/pathint_episodes.py`.
- 8 × 8 task: split seeds 84001–84005 (Phase F) and 84001–84003 (E0.9a, E6, rescaling); pools and per-length quotas are fixed in `tools/hard8x8_phaseF_fullscale_v1/PROTOCOL.json` and checked by episode fingerprints. Matched controls, ρ-series cores and fresh-random cores are rebuilt deterministically from the navigation core with `stable_seed32('matched_random', split)`, `stable_seed32('e6_rho_core', split)` and `stable_seed32('phaseF_fresh_random_core', source, split)`.

## Level 1

```bash
python figures/redraw_all_figures.py --aggregate data/aggregate_full --out outputs/figures
```
Output names follow the final numbering (`Figure2` … `Figure7`, `SupplementaryFigureS1` … `SupplementaryFigureS12`). Figure 1 and the graphical abstract are supplied as static images in `figures/figure1/`.

## Level 2

Extract P1–P3 into the repository root, then run the commands in the README. `reevaluate_models.py` rebuilds each model (navigation core from P1, transformation from the recorded seed, interface and readout from P2), evaluates the four test sets and compares the accuracies with the stored `metrics.csv` (tolerance 0.002). A mismatch returns a nonzero exit status. On Windows use a short root path and `release_tools/local/extract_packages.py`.

## Level 3

1. Pretraining: `python -m multinav.stage navigation --config <config>` and `python -m multinav.stage sequence_control --config <config>` with the per-source configurations (P3). The selected checkpoint is the one with the lowest navigation validation loss (`best.pt`) and, for the controls, `best_validation.pt`.
2. 4 × 4 experiments: `lsf_best_validation/run_best_validation_source.py --family main|adapter_symbolic|factorial` per source, then the aggregation in `topology/schoyen_formal_figureA3_patch_v1/unified_aggregate/`.
3. 8 × 8 task: `run_group.py` for every source × split × group, then `collect_fullscale.py` and the freeze script.
4. Mechanisms: `run_*.py` then `collect_*.py` in each `tools/mechanism_v1/*` folder, then `verdicts_v1/scripts/compute_verdicts.py`.
5. Topology: `topology/schoyen_topology_best_validation_cluster_v3/torus_chain.py`, then `topology/schoyen_formal_figureA3_patch_v1/run_figureA3_source.py`.
6. Figure source data: `figures/source_data_builders/prepare_source_data.py` (4 × 4 and topology folders), the Phase-F freeze script and the S12 exporter.

Scripts read and write below `NRT_PROJECT_ROOT` (default: the repository root).

## Software environment

For figure generation, use Python 3.11 and `requirements-figures.txt` (NumPy 1.24.3, pandas 2.2.3, Matplotlib 3.7.2, SciPy 1.11.1, Pillow 9.4.0). Target-model reconstruction additionally uses `requirements-model-checks.txt`, including PyTorch 2.7.0; choose a CPU/CUDA build for your hardware. These figure and example-model commands were run on Windows CPU with Python 3.11.5. The Linux training/topology environment is recorded separately in `requirements.txt`.

Random seeds, budgets, comparison families and frozen plan files are retained in `plan.json`, `configs/frozen_plan/` and the experiment-specific protocol files. Plot layout and fonts may differ slightly across platforms.
