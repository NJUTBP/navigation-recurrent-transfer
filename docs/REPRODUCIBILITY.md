# Reproduction guide

## Levels

| Level | What is reproduced | Needs | Hardware |
|---|---|---|---|
| 1 | Every computational figure from its source data, with the statistics stored next to it | this repository | CPU, about a minute |
| 2 | Accuracies, retention and source-side measures recomputed from trained networks | + P1, P2, P3 | GPU recommended |
| 3 | Networks retrained from code, configurations and seeds | + P1 (or retrain P1 too) | GPU, hours to days |

Coverage of Level 2: pretrained cores (Figs. 2, 7d, S1, S2, S11), Phase-F scalar-gain models (Figs. 6, S5, S8, 7a), E0.9a (S7), E6 and rescaling models (Figs. 7b–e, S12). The 4 × 4 experiments (Figs. 3–5, S4), the factorial path-invariance models (S2), the navigation-interface refits (S9) and the full-finetune conditions are reproduced at Levels 1 and 3.

## Seeds and data generation

- Navigation sources 6101–6110 and paired delayed-reconstruction sources 7101–7110 (`plan.json → source_pairs`, `configs/frozen_plan/config_frozen.yaml`).
- 4 × 4 tasks: three target-training repeats per source block with the seeds listed in `plan.json` (`main_target_seeds`, `factorial_target_seeds`); trials are random walks generated by `code/gpm_cmap/data/graph_tasks/pathint_episodes.py`.
- 8 × 8 task: split seeds 84001–84005 (Phase F) and 84001–84003 (E0.9a, E6, rescaling); pools and per-length quotas are fixed in `tools/hard8x8_phaseF_fullscale_v1/PROTOCOL.json` and checked by episode fingerprints. Matched controls, ρ-series cores and fresh-random cores are rebuilt deterministically from the navigation core with `stable_seed32('matched_random', split)`, `stable_seed32('e6_rho_core', split)` and `stable_seed32('phaseF_fresh_random_core', source, split)`.
- Statistics: source-bootstrap and permutation procedures use the seed `statistics_seed` = 982451653.

## Level 1

```bash
python figures/redraw_all_figures.py --aggregate data/aggregate_full --out outputs/figures
python figures/export_source_data_final.py --aggregate data/aggregate_full --out outputs/source_data_final
```

Output names follow the article numbering (`Figure2` … `Figure7`, `SupplementaryFigureS1` … `SupplementaryFigureS12`); `--figures` selects individual figures. Figure 1 and the graphical abstract are static images in `figures/figure1/`. Both tools refuse output folders inside the source data, and the export only replaces a folder that holds a previous export.

## Level 2

Extract P1–P3 into the repository root, then run the commands in the README. `reevaluate_models.py` rebuilds each model (navigation core from P1, transformation from the recorded seed, interface and readout from P2), evaluates the four test sets and compares the accuracies with the stored `metrics.csv` (tolerance 0.002). A mismatch returns a nonzero exit status. Missing packages are reported before any computation. On Windows use a short root path and `release_tools/local/extract_packages.py`.

## Level 3

1. Pretraining: `python -m multinav.stage navigation --config <config>` and `python -m multinav.stage sequence_control --config <config>` with the per-source configurations of P3 (`sources/nav_seed_<s>/configs/`). The selected checkpoint is the one with the lowest navigation validation loss (`best.pt`) and, for the controls, `best_validation.pt`.
2. 4 × 4 experiments: `lsf_best_validation/run_best_validation_source.py --family main|adapter_symbolic|hard|factorial` per source, then `topology/schoyen_formal_figureA3_patch_v1/unified_aggregate/aggregate_best_validation_full_v2.py`; 7,000-trial baseline points with `extensions/symbolic_baseline7000_extension_v1/`.
3. 8 × 8 task: `tools/hard8x8_phaseF_fullscale_v1/scripts/run_group.py` for every source × split × group, then `collect_fullscale.py` and `tools/FigureA5_PhaseF_workflow_v1/freeze_phaseF_figureA5_into_aggregate.py --aggregate <new aggregate>`.
4. Mechanisms: `run_*.py` then `collect_*.py` in each `tools/mechanism_v1/*` folder (dependencies in [tools/mechanism_v1/README.md](../tools/mechanism_v1/README.md)), then `verdicts_v1/scripts/compute_verdicts.py`.
5. Topology: `topology/schoyen_topology_best_validation_cluster_v3/torus_chain.py`, then `topology/schoyen_formal_figureA3_patch_v1/run_figureA3_source.py`.
6. Figure source data: `figures/source_data_builders/prepare_source_data.py` (4 × 4, pretraining and topology folders), the Phase F freeze script and the S12 exporter.

Scripts resolve the project root from `NRT_PROJECT_ROOT` (default: the repository root). The 8 × 8 and mechanism scripts write below `<project root>/rerun_best_validation/`, which is also where P3 is extracted; use a separate working copy for new runs. The multinav, best-validation and topology drivers write to the output root given on their command line (`outputs/multinav`, `--output-root`, `--result-root`).

## Checkpoints and configurations

All released results use, for every navigation source, the checkpoint with the lowest navigation validation loss (`best.pt`) and, for the delayed-reconstruction controls, `best_validation.pt`. New runs use `code/multinav/config.yaml` (`checkpoint_policy: best_validation`); `lsf_best_validation/run_best_validation_source.py` checks the rule against each source's `history.json`. The released weights are indexed in `data/source_level_results/checkpoint_provenance/`.

## Protocols

- 4 × 4 cohort: `plan.json` (identical copy in `configs/frozen_plan/`): sources, seeds, budgets and comparison contrasts.
- 8 × 8 task: `tools/hard8x8_phaseF_fullscale_v1/PROTOCOL.json` and `PREREGISTERED_ANALYSIS.md`.
- Mechanistic analyses: the decision rules in the collectors' module docstrings and in `tools/mechanism_v1/verdicts_v1/scripts/compute_verdicts.py`.
- Topology: `topology/schoyen_formal_figureA3_patch_v1/PROTOCOL_FIGUREA3_SCHOYEN_FORMAL.md`.

## Tests and release verification

`python -m pytest` (repository root) runs the contract tests: figure numbering and source data, seed blocks of the plan, the checkpoint layout of the data packages, statistics stored with the figure data, and the Phase F protocol, seeds, splits and model wrappers (the last group needs PyTorch and is skipped without it). `python release_tools/local/verify_release.py --repo .` checks every public file against `data/RELEASE_FILES.json` (size, SHA-256, Python syntax); `--packages /path/to/packages` also checks the three archives.

## Software environment

For figure generation, use Python 3.11 and `requirements-figures.txt` (NumPy 1.24.3, pandas 2.2.3, Matplotlib 3.7.2, SciPy 1.11.1, Pillow 9.4.0). Target-model reconstruction additionally uses `requirements-model-checks.txt`, including PyTorch 2.7.0; choose a CPU/CUDA build for your hardware. These figure and example-model commands were run on Windows CPU with Python 3.11.5. The Linux training/topology environment is recorded separately in `requirements.txt`. Plot layout and fonts may differ slightly across platforms.
